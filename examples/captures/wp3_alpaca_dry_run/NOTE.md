# Alpaca capture set — SYNTHETIC, and why

These envelopes are **synthetic and sanitized**, not a recording of a
real account. That is a limitation, and it is stated here rather than
papered over.

The WP3 order asked for a real read-only capture taken from existing
durable evidence rather than from a new connection. Both halves of
that are unavailable in this repository:

* the durable Alpaca evidence lives under the operator's private
  state tree, which this repository's own contributor rules forbid
  reading, copying or quoting into a public tree;
* opening a new connection to take one is exactly what the order
  forbids, and this package holds no credential and no client.

So the capture that exists is synthetic, and it asserts **typed
absence** rather than invented facts: no position and no order. An
empty book is a claim the parser can check; a fabricated bracket
would be a claim about an account nobody observed.

What this costs, precisely: the Alpaca *bracket* shape is exercised
only by unit fixtures, never by a recorded payload. The bracket
parser's structural role derivation is therefore verified against the
documented API shape and the repository's own existing order
fixtures, not against a capture.

Obtaining a real capture requires an operator to export a sanitized
read-only snapshot from the private evidence tree. That is an owner
action, proposed and not performed.
